# 1. Overview

This directory contains the product-level requirements, specifications, business rules, user workflows and release planning documents for Niyuvia.

These documents establish what the product should accomplish, who it serves, how users interact with it and how product success will be evaluated.

They provide the foundation for technical architecture, implementation and quality assurance.

# 3. Document Relationships

The product documentation follows this logical structure:

1. Product vision establishes the long-term direction.
2. PRD defines the product requirements.
3. Personas identify the intended users.
4. Functional requirements describe system behaviour.
5. User stories describe user needs.
6. Workflows describe how users complete tasks.
7. Non-functional requirements define quality expectations.
8. Business rules establish operational constraints.
9. Security and privacy requirements establish protection expectations.
10. MVP scope defines the initial release.
11. Traceability connects requirements to verification.
12. Product metrics define how success is measured.
13. Assumptions and risks identify unresolved uncertainties.

# 4. Documentation Governance

All documents in this directory are currently drafts.

They must undergo a consolidated review before being treated as approved product specifications.

A document's existence does not mean its requirements have been implemented or verified.

## Review Status Definitions

| Status | Meaning |
|---|---|
| Draft | Initial document created |
| Under Review | Content and consistency being checked |
| Approved | Reviewed and accepted as the current specification |
| Superseded | Replaced by a newer approved version |

# 5. Change Management

When a product requirement changes:

1. Identify the affected requirement.
2. Review dependent user stories.
3. Review affected workflows.
4. Review business rules.
5. Review MVP scope.
6. Update the traceability matrix.
7. Identify affected technical architecture and tests.

Changes must be documented rather than silently modifying expected behaviour.

# 7. Important Project Principle

Niyuvia is being developed initially as a zero-budget portfolio MVP.

Commercial production readiness will be treated as a separate engineering and business milestone.

Product documentation, implementation status, test results and production readiness must always be reported accurately.
